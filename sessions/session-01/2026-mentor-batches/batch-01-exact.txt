# 🐼 Batch 01 — Your First Day Working with Java

<text color="secondary" size="sm" weight="medium">JAVA CORE · LECTURE 01 · BATCH 01 OF 12</text>

**Today's interview question: What is Java, what is the difference between JDK, JRE, and JVM, and how do developers set up their Java development environment?**

**Characters:** 🐯 Mentor — a Java developer with five years of industry experience. 🐼 Student — recently finished Java in college but has never worked on a software development team.

**Our goal today:** Understand what happens between writing Java code and seeing the program run. We'll use Java 21 and IntelliJ IDEA.

---

## 🐯 Step 1 — Welcome to your first development task

**Mentor:** Good morning! Welcome to our development team.

Before we start building applications, I want to understand something.

Have you written Java programs before?

**Student:** Yes. In college, I learned classes, objects, inheritance, and a little bit of collections.

**Mentor:** Great! How did you execute your Java programs?

**Student:** I used an IDE. I wrote the program, clicked Run, and got the output.

**Mentor:** Excellent. Let me ask you another question.

When you clicked Run, did you ever wonder what was actually happening behind that button?

**Student:** Not really. I thought the IDE just executes the Java code.

**Mentor:** That's what many beginners think!

But the IDE is not the thing that actually understands and executes Java bytecode.

Let's investigate what happens behind the scenes.

Imagine you're given this program:

```java id="x8h9xq"
public class Main {

    public static void main(String[] args) {
        System.out.println("Hello, Developer!");
    }
}
```

**Mentor:** What output do you expect?

**Student:** `Hello, Developer!`

**Mentor:** Correct. Now imagine I give you a brand-new laptop.

You install IntelliJ IDEA, paste this program, and click Run.

But the IDE displays:

```text id="pe3s99"
No JDK configured
```

**Student:** Wait! I installed IntelliJ. Why can't it run Java?

**Mentor:** Excellent question.

That is our first problem.

---

## 🦊 Step 2 — Why isn't IntelliJ enough?

**Mentor:** Think about IntelliJ as your development workspace.

It provides features such as:

- A code editor.
- Syntax highlighting.
- Suggestions while writing code.
- Debugging tools.
- A Run button.

But IntelliJ needs a Java development environment to compile and run your Java application.

**Student:** What is that development environment?

**Mentor:** It's called the **JDK — Java Development Kit**.

Think of it this way:

```text id="w5aj8p"
IntelliJ IDEA
    |
    | You write Java code
    |
    ↓
JDK
    |
    | Provides tools to compile Java
    |
    ↓
JVM
    |
    | Executes Java bytecode
    |
    ↓
Program Output
```

**Student:** So IntelliJ and JDK are different things?

**Mentor:** Exactly!

IntelliJ is the tool we use to develop applications.

The JDK provides the Java compiler, runtime, and other development tools.

You can even compile and run Java without IntelliJ.

**Student:** Really? How?

**Mentor:** We'll try that shortly.

But first, let's understand why the JDK is necessary.

---

## 🐨 Step 3 — Your computer doesn't understand Java directly

**Mentor:** Look at this Java statement.

```java id="rpi9uf"
System.out.println("Hello");
```

Can your computer's CPU directly understand this statement?

**Student:** I guess not. The CPU understands machine instructions.

**Mentor:** Exactly.

Your CPU doesn't directly execute Java source code.

We need to translate the program into something that can eventually be executed by the machine.

**Student:** So Java uses a compiler?

**Mentor:** Correct!

The JDK includes a Java compiler called `javac`.

Suppose your Java program is saved as:

```text id="00tc0y"
Main.java
```

You can use the compiler:

```bash id="vl5zi0"
javac Main.java
```

The compiler produces another file:

```text id="8zk8dr"
Main.class
```

**Student:** What's inside `Main.class`?

**Mentor:** Java bytecode.

That is an intermediate instruction format used by the JVM.

```text id="gmz2x3"
Main.java
    |
    | Java source code
    ↓
  javac
    |
    | Compilation
    ↓
Main.class
    |
    | Java bytecode
    ↓
   JVM
    |
    | Executes the program
    ↓
  Output
```

**Student:** So `javac` doesn't directly produce Windows machine instructions?

**Mentor:** Correct. It produces Java bytecode.

The JVM executes that bytecode using mechanisms such as interpretation and Just-In-Time compilation.

We'll investigate the JVM execution engine in a later batch.

For now, remember one important distinction.

**The Java compiler produces bytecode. The JVM executes bytecode.**

---

## 🐯 Step 4 — Why is Java called platform-independent?

**Student:** I've heard that Java is platform-independent. Is that related to bytecode?

**Mentor:** Exactly!

Imagine we develop a Java application on Windows.

Our compiler produces:

```text id="30w5du"
Main.class
```

Now we want to run that same application on Linux.

Do we necessarily need to rewrite the Java source code?

**Student:** No?

**Mentor:** Correct, provided the application uses compatible Java APIs and platform-independent dependencies.

A compatible JVM can execute the same Java bytecode on different operating systems.

**Student:** So the JVM is different for each operating system?

**Mentor:** Yes. JVM implementations are built for particular operating systems and processor architectures.

But each compatible implementation follows the Java Virtual Machine specification.

That's one reason Java became popular for enterprise development.

**Student:** Is this what people mean by "Write Once, Run Anywhere"?

**Mentor:** Exactly. Although applications that depend on operating-system-specific native libraries or features might need additional work.

## 🦊 Step 5 — JDK vs JRE vs JVM

**Student:** I'm getting confused. We have three terms now: JDK, JRE, and JVM.

Are they all different?

**Mentor:** Yes. Let's understand them using one simple situation.

Imagine you want to create a Java application.

You need something that can compile your source code.

That is why you need a JDK.

Now imagine someone only wants to run an already compiled application.

They need a suitable Java runtime environment.

Historically, that runtime was commonly distributed separately as the JRE.

And the JVM is the actual virtual machine within the runtime.

Here's a simplified picture:

**Student:** Can you explain each one in one sentence?

**Mentor:** Sure.

| Component | Simple meaning |
|---|---|
| **JDK** | Provides tools to develop, compile, and run Java |
| **JRE** | Provides the environment needed to run Java applications |
| **JVM** | Executes Java bytecode |

**Student:** So if I'm writing Java applications in IntelliJ, I need a JDK?

**Mentor:** Correct.

And when you install a modern JDK, it already includes the runtime components necessary to execute Java applications.

## 🐨 Step 6 — Why are we using Java 21?

**Student:** In my lecture, they mentioned Java 8 and Java 21.

Why are we starting with Java 21 instead of Java 8?

**Mentor:** Good question!

Java has multiple versions.

Over time, the language and platform gain new features and improvements.

For example:

| Java version | Examples of significant features |
|---|---|
| Java 8 | Lambda expressions, Stream API |
| Java 11 | Standard HTTP Client API |
| Java 17 | Sealed classes |
| Java 21 | Virtual threads, sequenced collections |

Java 21 is a Long-Term Support (LTS) release.

**Student:** Does that mean Java 8 is useless now?

**Mentor:** Absolutely not!

Java 8 is older, but its core concepts remain important, and existing enterprise applications may still use it.

For example, we still need to understand classes, objects, inheritance, exceptions, collections, and the Stream API.

**Student:** So learning Java 21 doesn't mean skipping Java fundamentals?

**Mentor:** Exactly!

Think of it like learning to drive a modern car.

You still need to understand steering, braking, and traffic rules.

Additional features don't eliminate the fundamentals.

**Student:** What are virtual threads?

**Mentor:** They're a Java 21 feature that can help applications handle many concurrent tasks efficiently, especially when tasks spend time waiting on I/O.

But we won't study them today.

First, you need to understand ordinary Java threads.

Then we can discover what problem virtual threads were designed to solve.

**Student:** That makes sense. So we're using Java 21 as our learning environment, while covering Java fundamentals and important features from earlier versions.

**Mentor:** Exactly.

Open the terminal in the directory containing `Main.java`.

## 🦁 Step 9 — Your first environment-related failure

**Mentor:** Now imagine you write your program using JDK 21.

You compile it successfully.

Then someone tries to run the compiled class using a Java 8 runtime.

What could happen?

**Student:** Maybe it won't work?

**Mentor:** Correct.

You may see an error resembling:

```text id="hw1n0q"
UnsupportedClassVersionError
```

**Student:** What does that mean?

**Mentor:** The runtime may be too old to understand the version of the class file produced by the compiler.

For example:

```text id="pgr7zm"
Java 21 compiler
       ↓
  Main.class
       ↓
Java 8 runtime
       ↓
Cannot load newer class-file version
```

**Student:** So having Java installed isn't enough. The version also matters?

**Mentor:** Exactly!

This is why developers check the Java version when setting up or troubleshooting an application.

You might have multiple JDKs installed, with your IDE configured to use one and your terminal configured to use another.

**Student:** How do I identify that?

**Mentor:** Start with:

```bash id="y00hyg"
java -version
javac -version
```

Then check which JDK is configured in your IntelliJ project.

On systems with multiple installations, you may also need to inspect the `PATH` environment variable and `JAVA_HOME`.

We will explore those when we study Java environment configuration in more detail.

**Student:** So the problem may not be in my Java code at all?

**Mentor:** Exactly.

Sometimes your code is correct, but your development environment is configured incorrectly.

Learning to distinguish those problems is an important development skill.

## 🎯 Today's interview-ready answer

**Student:** If an interviewer asks, "What is Java, and explain JDK, JRE, and JVM," what should I say?

**Mentor:**

> Java is an object-oriented, class-based programming language widely used for developing backend, enterprise, and other applications.
>
> Java source code is typically compiled into bytecode using the Java compiler.
>
> The JDK, or Java Development Kit, provides the tools required to develop and compile Java applications, including the `javac` compiler.
>
> The JRE, or Java Runtime Environment, consists of the runtime components required to execute Java applications.
>
> The JVM, or Java Virtual Machine, executes Java bytecode.
>
> Because compatible JVM implementations are available on different operating systems, Java bytecode can run across different platforms.
>
> In my development environment, I can use IntelliJ IDEA with a configured JDK to write, compile, debug, and run Java applications.

### 🧠 One-line memory trick

**IntelliJ → Write Java → JDK → `javac` → Bytecode → JVM → Execute → Output**
